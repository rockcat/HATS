Setup

Prerequisites

The server is a single Node.js process. Avatar rendering and speech synthesis pull in native addons that require system libraries at install time.

Required

  • Node.js 20+ — node --version to verify. Download from nodejs.org.
  • npm 10+ — bundled with Node.js 20.
  • An Anthropic API key — agents default to Claude Haiku. Other providers are optional.

Native addon build deps (Linux / CI)

These packages are needed when running npm ci on Linux so that @napi-rs/canvas, gl, and @kmamal/sdl can compile their C++ addons.

# Debian / Ubuntu
sudo apt-get install -y \
  build-essential pkg-config \
  libcairo2-dev libpango1.0-dev libjpeg-dev libgif-dev \
  libgl1-mesa-dev libglu1-mesa-dev libxi-dev libxext-dev \
  libsdl2-dev

Optional

  • Python 3.9+ — required for Piper TTS (avatar speech). The PYTHON_BIN env var selects the executable (default: python; use py on Windows).
  • ffmpeg — used by fluent-ffmpeg for media processing.
  • Rhubarb — lip-sync binary, placed at runtime_data/rhubarb/rhubarb (or .exe on Windows).
Setup

Repository Layout

The repo is a monorepo with three top-level areas: the API server source, UI apps, and runtime data.

HATS/ ├── server/ API server (TypeScript) │ ├── src/ Source modules │ │ ├── api/ HTTP + WebSocket server, routers │ │ ├── orchestrator/ Agent orchestration │ │ ├── mcp/ MCP server / client │ │ ├── speech/ Piper TTS voice manager │ │ ├── providers/ AI provider adapters │ │ └── team-runner.ts Entry point │ ├── dist/ Compiled output (gitignored) │ ├── tsconfig.json TypeScript config (rootDir: .., so output nests) │ └── package.json Server-scoped build scripts │ ├── apps/ │ ├── web/ Browser UI (ES modules, no bundler) │ ├── electron/ Electron desktop wrapper │ ├── admin/ placeholder │ ├── agent_manager/ placeholder │ └── flutter/ placeholder │ ├── runtime_data/ All files read/written at runtime │ ├── avatars/ GLB / VRM avatar models + backgrounds │ ├── config/ mcp-catalogue.json │ ├── data/ model-pricing.json, telemetry │ ├── projects/ gitignored — per-project state │ ├── piper_voices/ gitignored — .onnx voice models │ └── rhubarb/ Rhubarb binary │ ├── scripts/ kanban-mcp.ts, download-voices.mjs, setup scripts ├── tools/ Developer utilities ├── package.json Root — npm scripts, all deps └── tsconfig.json Root — delegates to server/tsconfig.json

The RUNTIME_DIR env var overrides the base path for runtime_data/. Default: <cwd>/runtime_data.

Setup

Quick Start (local dev)

1
Clone and run the setup script 
# Windows
scripts\setup.bat

# macOS / Linux / Git Bash
bash scripts/setup.sh

This checks Node.js, runs npm install, creates .env from .env.example, and downloads default Piper voices.

2
Fill in API keys in .env 
ANTHROPIC_API_KEY=sk-ant-...

At minimum, set ANTHROPIC_API_KEY. Other provider keys are optional — agents use Anthropic by default.

3
Start the server 
npm start
4
Open the UI

Navigate to http://localhost:3001

Development mode npm run dev uses tsx for instant TypeScript execution — no build step needed. Changes to server/src/ take effect on the next restart.

Reference

Runtime Data

Everything the server reads or writes at runtime lives under runtime_data/. This directory is separate from source so it can be bind-mounted as a Docker volume, excluded from builds, and managed independently.

PathTrackedContents
runtime_data/avatars/ Git GLB and VRM avatar models; background images.
runtime_data/config/ Git mcp-catalogue.json — MCP server definitions.
runtime_data/data/ Git model-pricing.json, telemetry files.
runtime_data/projects/ Gitignored Per-project state: agent snapshots, events, kanban board, meetings.
runtime_data/piper_voices/ Gitignored .onnx voice models downloaded by scripts/download-voices.mjs.
runtime_data/rhubarb/ Git (placeholder) Place the Rhubarb binary here. All binaries are gitignored; only the placeholder file is tracked.
runtime_data/outputs/ Git Agent-generated file outputs.
New installs The gitignored directories (projects/, piper_voices/) are created automatically on first startup. You do not need to create them manually.
Production

TypeScript Build

The server source in server/src/ is plain TypeScript targeting Node.js with NodeNext module resolution. The web UI in apps/web/ is already browser-native ES modules — no compile step needed for the frontend.

shell
npm run build
# → runs: tsc -p server/tsconfig.json
# → output: server/dist/

Alternatively, build from inside the server directory:

cd server && npm run build

The compilation root is the repo, not server/src, because the server imports from packages/. So the output nests the whole source path under server/dist/ — a longer path than people expect, and the reason a hand-written path to a compiled file is usually wrong:

server/dist/ ├── server/src/ │ ├── team-runner.js ← entry point │ ├── api/ │ ├── orchestrator/ │ └── util/runtime-dir.js └── packages/ Shared contracts and clients

Running compiled JS

node --env-file=.env server/dist/server/src/team-runner.js
Built-in MCP servers The kanban board and the per-agent calendar are our own code, spawned as subprocesses. Which file is run is decided when they start: the compiled output if this checkout has been built, otherwise the TypeScript source through tsx. Nothing needs building for them to work, and no path to them is written down — an earlier version named a compiled path by hand and went on working only because a stale copy from an older layout was still lying around.
Production

Deploying

Direct (with tsx, simplest)

No build step required. Suitable for a VPS or bare-metal server where you can install Node.js and clone the repo.

git clone <repo> /opt/hats
cd /opt/hats
npm ci
cp .env.example .env   # then fill in keys
node --env-file=.env --import tsx/esm server/src/team-runner.ts

As a systemd service

ini /etc/systemd/system/hats.service 
[Unit]
Description=HATS multi-agent server
After=network.target

[Service]
Type=simple
User=hats
WorkingDirectory=/opt/hats
EnvironmentFile=/opt/hats/.env
ExecStart=/usr/bin/node --import tsx/esm server/src/team-runner.ts
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
systemctl daemon-reload
systemctl enable --now hats
journalctl -u hats -f     # follow logs

Port and reverse proxy

The server listens on port 3001 by default. For HTTPS, place nginx or Caddy in front:

nginx
location / {
    proxy_pass         http://localhost:3001;
    proxy_http_version 1.1;
    proxy_set_header   Upgrade $http_upgrade;
    proxy_set_header   Connection "upgrade"; # WebSocket
    proxy_set_header   Host $host;
    proxy_read_timeout 3600s;
}

The WebSocket connection (/ws) requires the Upgrade headers above. The proxy_read_timeout should be long enough to keep SSE streams alive.

Production

Dockerfile

A multi-stage build: the builder stage installs all dependencies and compiles TypeScript; the runner stage copies the compiled artifacts and only the shared libraries needed at runtime.

Native addons The builder and runner must use the same base image so the compiled .node files match the glibc version in the runner. Switching from node:22-slim to node:22-alpine between stages will break native addons.
dockerfile Dockerfile 
# syntax=docker/dockerfile:1

# ─── Stage 1: builder ────────────────────────────────────────────────────────
FROM node:22-slim AS builder
WORKDIR /build

# Build-time deps for native Node addons:
#   @napi-rs/canvas → Cairo + Pango
#   gl              → Mesa OpenGL (headless rendering)
#   @kmamal/sdl     → SDL2
RUN apt-get update && apt-get install -y --no-install-recommends \
      python3 build-essential pkg-config \
      libcairo2-dev libpango1.0-dev libjpeg-dev libgif-dev \
      libgl1-mesa-dev libglu1-mesa-dev libxi-dev libxext-dev \
      libsdl2-dev \
    && rm -rf /var/lib/apt/lists/*

# Install deps first — this layer is cached until package*.json changes
COPY package*.json ./
RUN npm ci

# Source files
COPY server/tsconfig.json ./server/tsconfig.json
COPY server/src/          ./server/src/
COPY apps/web/            ./apps/web/
COPY scripts/             ./scripts/

# Compile TypeScript → server/dist/
RUN npm run build


# ─── Stage 2: runner ─────────────────────────────────────────────────────────
FROM node:22-slim AS runner
WORKDIR /app

# Runtime shared libraries (not -dev headers)
RUN apt-get update && apt-get install -y --no-install-recommends \
      python3 python3-pip \
      libcairo2 libpango-1.0-0 libpangocairo-1.0-0 libjpeg62-turbo libgif7 \
      libgl1-mesa-glx libglu1-mesa libxi6 libxext6 \
      libsdl2-2.0-0 \
      ffmpeg \
    && rm -rf /var/lib/apt/lists/*

# Piper TTS Python package (flask = HTTP server shim)
# --break-system-packages required on Debian 12+ / bookworm
RUN pip3 install --no-cache-dir --break-system-packages piper-tts flask

# node_modules carries compiled .node files AND tsx (needed for the
# kanban MCP subprocess: node --import tsx/esm scripts/kanban-mcp.ts)
COPY --from=builder /build/node_modules ./node_modules
COPY --from=builder /build/server/dist  ./server/dist
COPY --from=builder /build/apps/web     ./apps/web
COPY --from=builder /build/scripts      ./scripts
COPY package.json ./

# runtime_data/ is always mounted — never bake project data into the image.
# The volume must contain at minimum: avatars/, config/, data/
VOLUME ["/app/runtime_data"]

EXPOSE 3001
# Piper TTS servers (one per voice model, starting at PIPER_SERVER_PORT_START)
EXPOSE 5100-5120

ENV NODE_ENV=production \
    RUNTIME_DIR=/app/runtime_data

CMD ["node", "server/dist/team-runner.js"]

Building and running

docker build -t hats .

docker run -d \
  --name hats \
  -p 3001:3001 \
  -p 5100-5120:5100-5120 \
  -v $(pwd)/runtime_data:/app/runtime_data \
  --env-file .env \
  -e RUNTIME_DIR=/app/runtime_data \
  hats
Production

Docker Compose

yaml docker-compose.yml 
services:
  hats:
    build: .
    image: hats:latest
    restart: unless-stopped
    ports:
      - "3001:3001"
      # Piper TTS HTTP servers — one per loaded voice model
      - "5100-5120:5100-5120"
    volumes:
      # Bind-mount runtime data — survives container restarts and rebuilds
      - ./runtime_data:/app/runtime_data
    env_file:
      # Docker injects these directly; no --env-file flag needed in CMD
      - .env
    environment:
      NODE_ENV: production
      RUNTIME_DIR: /app/runtime_data
      PIPER_VOICES_DIR: /app/runtime_data/piper_voices
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3001/api/state"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 15s
docker compose up -d          # start
docker compose logs -f hats   # follow logs
docker compose pull && docker compose up -d  # update
First run Before starting the container, ensure runtime_data/config/mcp-catalogue.json and runtime_data/data/model-pricing.json exist — they are tracked in git and should be present in the bind-mounted directory. The projects/ and piper_voices/ subdirectories are created automatically.
Optional Components

Piper TTS

Piper provides avatar speech synthesis. The server supports two modes:

Python HTTP server (recommended)

Requires Python 3.9+ with piper-tts and flask.

pip install piper-tts flask      # or: py -m pip install ... (Windows)

The voice manager discovers all .onnx files in runtime_data/piper_voices/ and starts one Flask server per model, beginning at port 5100.

Download voices:

node scripts/download-voices.mjs

Native binary

Place the Piper native binary at runtime_data/piper/piper (or piper.exe on Windows) and set:

PIPER_BIN=runtime_data/piper/piper.exe
Windows Python If python is not in PATH, set PYTHON_BIN=py in your .env. The voice manager reads this env var before spawning piper processes.
Optional Components

Rhubarb Lip Sync

Rhubarb analyses audio and outputs phoneme timings for avatar mouth animation. Without it, lip sync is disabled but all other features work normally.

  1. Download the release for your platform from github.com/DanielSWolf/rhubarb-lip-sync
  2. Place the binary at runtime_data/rhubarb/rhubarb (Linux/macOS) or runtime_data/rhubarb/rhubarb.exe (Windows)
  3. Set RHUBARB_BIN=runtime_data/rhubarb/rhubarb in .env if you use a non-default path
Containers Rhubarb binaries are platform-specific. For Docker (Linux), download the Linux release and place it in the bind-mounted runtime_data/rhubarb/ directory on the host.
Optional Components

Electron Desktop

The Electron wrapper in apps/electron/ opens a browser window pointed at the API server. The server must be running separately.

Development

# Terminal 1: start the API server
npm start

# Terminal 2: launch the Electron window
npm run electron:run

Package for distribution

npm run electron:build
# → dist-desktop/ contains the packaged app
Self-contained packaging The current electron:build packages the web UI but not the Node.js server. A fully self-contained desktop app would need the Electron main process to spawn server/src/team-runner.ts as a child process and bundle all server dependencies.
